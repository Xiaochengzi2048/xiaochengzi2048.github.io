能力逐项对比

能力维度 Kiro Crew Hermes Agent 差异要点
底座 / 模型 Kiro CLI（专有，按 credit 计费）★ 模型无关，任意 provider Hermes 底层不锁供应商
持久记忆 Memory + 工作区级 lessons，向量+全文检索知识图谱 memory / user profile + skills，Markdown 可编辑 对等 =
技能 / 自进化 重复模式→可复用 skill（Markdown） skill_manage / skill_view（Markdown+frontmatter） 对等 =
纠正→教训 corrections 变 durable lessons 教训写入 memory 教训段 对等 =
多 agent 编排 ACP 并行 subagent · Activity view 一 agent 一卡片强 delegate_task 并行/批量，结果回灌父对话 Crew 实时可视化更强
定时 / 触发 cron + webhook + heartbeat + CI/CD 反应式多 cronjob（cron / 一次性 / watchdog） Crew 触发源更丰富
多渠道接入 Slack/Discord/Telegram/Teams/Webex/WeCom/微信 Telegram/Feishu/微信/Discord/Slack… 几乎一致，Crew 多 Webex
安全 / 治理 7 层：沙箱·命令黑名单·bash 拦截·路径保护·凭证脱敏·签名审计日志·审批门重 沙箱 · 危险命令确认 · 敏感路径保护 Crew 企业级更重
App / UI 层 App SDK（TS/Python+React）· app store · DevFleets / Issue Radar / Code Review Sage生态 TUI + 平台原生渲染，无独立 App 层 最大结构性差异
协议标准 ACP + MCP（开放标准） MCP（native + mcporter）+ ACP 子 agent 对等 =
部署 / 定价 自托管（Mac/容器/VM），Crew 本体免费；连接的 AI/工具付费 自托管，模型成本随所选 provider 两者皆可留在企业边界内

Kiro Crew 更适合

  • 企业工程团队：平台 / DevOps / SRE 场景
  • 需要审批门 + 签名审计的合规环境
  • 已在用 Kiro 生态（复用 .kiro 配置）
  • 要把分散的"影子 agent"收编到统一工作台
  • 看重可视化编排与开箱即用 App

Hermes Agent 更适合

  • 个人 / 小团队的贴身通用 agent
  • 不想被单一 CLI / 模型供应商锁定
  • 轻量、灵活、快速定制 skill 的场景
  • 多模型自由切换与成本控制
  • 开源可改、无独立重 UI 负担
