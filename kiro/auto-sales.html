面向汽车行业客户的卖点与风险对照

一页纸销售参考：自主 AI 工程工作台如何切入车企的平台 / DevOps / SRE 场景，以及落地前必须诚实说清的约束。
适用对象：车企平台工程 / 研发效能 / 云与合规团队　·　销售视角速记
1

核心卖点（Sales Angles）

✓数据主权：自托管，代码凭证不出边界
开源可自托管在客户自有基础设施（VM / 容器），代码和凭证留在企业内网，不发往黑盒 agent。
话术："车企最敏感的源码与产线凭证，全程留在你们的合规边界内。"
✓把"影子 AI"收编成受治理工作台
当前开发者各自拿自己的凭证接 agent、无人追踪。Crew 提供统一入口 + 审批门 + 日志：什么跑了、碰了什么、谁授权的，一处可查。
话术："从失控的影子 IT，到可审计、可授权的统一队伍。"
✓无人值守跑长任务
依赖升级、框架迁移、flaky 测试清理、工单三线分诊、首轮事故排查——跨会话、带 checkpoint 与重试，会中 / 下班 / 睡觉时照常推进。
话术："多小时的迁移任务，你开完会回来看结果，而不是盯着提示词。"
✓合规友好：签名审计 + 人审门
7 层防御含签名审计日志、敏感路径保护、凭证脱敏、工具调用可要求人工审批——为车企功能安全 / 数据合规提供低风险的 agent 采纳路径。
话术："每一步都有签名留痕，审计和监管问得出、答得上。"
✓Crew 本体免费 + 开放标准
软件本体开源免费，基于 ACP / MCP 开放标准，兼容既有 MCP server、IDE 插件、CI 管线——增量叠加，不推翻现有工具链。
话术："先叠加到现有研发流程试点，不用推倒重来。"
✓已在 Amazon 内部大规模验证
前身 MeshClaw 在 Amazon 内部半年被 3.9 万+ 工程师采用、约 500 名贡献者——面对真实生产级安全要求打磨过。
话术："这是 Amazon 自己工程团队每天在用的东西。"
2

风险与需诚实说清的约束

高
底座 Kiro CLI 是专有且按 credit 计费"开源"止于编排层。想换 Claude Code / Codex / Devin 跑，需自建并验证连接器，发稿时尚无公开成功案例。
应对：先明确客户是否接受 Kiro CLI 生态与其计费模型；把"开源"边界讲清，避免过度承诺。
高
并行 agent 放大成本成本不止 token——多 agent 会成倍放大 model call、compute、CI 活动、API 用量与人工复核。多数企业目前还难以度量单个 agent 的成本与价值。
应对：落地前建立成本度量口径；先小范围试点，设并发上限与预算护栏，再放量。
中
需先落地一套治理策略最小权限、人工审批流、内存保留规则、代码来源追溯、可审计标准——这些是部署前提，不是部署后再补。
应对：把治理清单作为 POC 的一部分交付，帮客户把策略先立起来（见下方清单）。
中
运维成熟度门槛自托管 + 多 agent 编排对客户平台团队的运维能力有要求；心跳监控、审计日志需要有人真正去看。
应对：评估客户平台团队现状；必要时配 AWS ProServe / 合作伙伴做落地陪跑。
中
发布仍处早期（2026-08）刚开源，参考 App 与生态在快速迭代；企业级长期支持与路线图仍在演进（开放治理，社区共建）。
应对：定位为"前瞻试点"而非核心产线依赖；锁定用例后分阶段推进。
3

部署前治理清单（POC 交付项）

  • 最小权限访问（least-privilege）已定义
  • 人工审批工作流已配置
  • 内存 / 上下文保留规则已明确
  • 代码来源与产出可追溯
  • 签名审计日志接入客户 SIEM
  • 并发 agent 上限与预算护栏
  • 成本度量口径（超越 token）已建立
  • 敏感路径 / 凭证脱敏规则校验
  • Kiro CLI 计费模型客户已接受
  • 试点用例与成功指标已锁定
