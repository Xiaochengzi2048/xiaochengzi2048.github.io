🤖 Agent/编程

① Claude Code 上下文窗口管理技巧
Claude Code 的 100 万 token 超长上下文窗口是把双刃剑——虽然支持更复杂任务，但也可能带来上下文污染问题。开发者可通过设置 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 环境变量（如 40 万 token）来自定义自动压缩阈值，从而更好地管理会话质量。
🔗 https://x.com/trq212/status/2044654705780179011

② Cursor Canvas：为 Agent 构建自定义 UI
Cursor 推出 `/canvas` 功能，允许开发者为自己的 Agent 构建自定义交互界面，展示了 Agent 工具链正在向更丰富的 UI 层演进。这被视为 Agent 交互未来形态的一个缩影。
🔗 https://x.com/ryolu_/status/2044493859821129992

③ "软件工厂"即产品——Claude Code 驱动设计工具
Vercel CEO rauchg 展示了用 Claude Code + Three.js + Next.js 构建的"Shader Lab"设计工具，认为未来设计的核心不是某个具体工具，而是每个团队都能用 AI 搭建专属"设计工厂"的能力。"软件工厂本身就是产品"成为新范式。
🔗 https://x.com/rauchg/status/2044445445636972578

④ 子 Agent 编排与 Boss Agent 架构
swyx 指出"子 Agent 年"更多是优化问题，而真正的能力挑战在于反向问题：如何构建能够组合、调度和查询下层 Agent 的"Boss Agent"。他表示作为顾问参与设计了 Cog 的新 Spaces 架构。
🔗 https://x.com/swyx/status/2044636275375067440

🔒 安全

⑤ OpenClaw 安全加固进展
OpenClaw（开源 Claude 客户端）经过数千小时迭代，已建立完善的安全体系：支持 Docker/OpenShell 沙箱、白名单机制、逐次执行权限提示，并经过数百名安全研究人员渗透测试。garrytan 也表示基于 git+postgres 的 GBrain 已能良好支持多 Agent 并发，并称"OpenClaw 不安全"的时代已过去。
🔗 https://x.com/steipete/status/2044482797449150520 · https://x.com/garrytan/status/2044677189896220927

⑥ AI 自动化漏洞挖掘与开源安全度量
Replit CEO amasad 提出：如果前沿模型（如 Mythos）能全自动发现安全漏洞，GitHub 应该引入类似 Star 的新指标，显示每个开源包被投入了多少 AI 安全计算资源（如"$239M 算力已用于加固此包"），这或将成为开源软件可信度的新标准。
🔗 https://x.com/amasad/status/2044440298995228816

⑩ AI 将创造更多就业岗位的逻辑
Box CEO levie 认为 AI 会在很多行业创造更多工作岗位，原因在于：AI 加速了某一环节的产出，但随即会在流程的下一个瓶颈处暴露出新的人力需求。他以法律行业为例说明，更多人询问法律建议反而会带来更多律师需求。
🔗 https://x.com/levie/status/2044621545348481285

🎙 Podcast

The AI Model Built for What LLMs Can't Do

Logical Intelligence的创始人兼CEO Eve指出，AI行业存在一个关键盲区：部署在芯片设计和代码生成等关键系统中的大语言模型（LLM），其输出结果几乎没有人在严格验证其正确性。她的公司正在构建一种名为能量基模型（EBM）的全新架构——该模型无需token、非自回归，能够同时纵观所有可能的解题路径，从根本上消除了LLM因逐token"猜测"而导致幻觉的结构性缺陷。与LLM输出前完全不透明的黑箱特性不同，EBM允许在处理过程中随时检查模型内部状态，实现一种LLM在架构上无法做到的自对齐与内部验证。Logical Intelligence将这种内部可验证性与Lean4等外式形式化验证工具相结合，构建双重正确性校验机制，同时在计算成本上也远低于为LLM外挂验证器的方案。
