Sam Altman 宣布 Codex 周活跃用户达到 300 万，为庆祝这一里程碑，OpenAI 重置了使用限制。他表示未来每新增 100 万用户将持续重置，直至 1000 万用户。

③ Claude Code 安全沙箱绕过问题
Garry Tan 指出 Claude Code 存在一个有趣的安全盲点：虽然限制了 Write File 工具在工作区外的使用，但 Agent 仍可通过 bash 的 `cat >>` 命令向文件系统任意位置写入文件。这揭示了以工具级别限制来约束 Agent 行为时，底层 shell 访问权限可能成为绕过路径。
🔗 https://x.com/garrytan/status/2041750093414731888

④ CodexBar 0.20 更新：新增供应商与成本追踪
CodexBar 发布 0.20 版本，新增 Perplexity 和 OpenCode Go 两个提供商，现已支持 16 个 AI 提供商的菜单栏追踪。本次更新修复了 Claude token/成本重复计算导致的虚高问题，并支持无需重新登录切换 Codex 账户。
🔗 https://x.com/steipete/status/2041731877787025448

⑤ Agent 验证中的 token 效率问题
经过约 10 次用户访谈和大量转录分析，发现开放式验证（open-ended verification）会消耗大量 token 却不能有效提升输出质量。作者计划撰写文章分享如何高效设计 Agent 验证流程，避免无效消耗。
🔗 https://x.com/trq212/status/2041722125510377705

🔒 安全

⑥ Prompt Injection 命名与安全概念传播
swyx 引用 Simon Willison 的观点，探讨安全概念命名的重要性——"prompt injection" 之所以广为人知，部分原因在于其名称直观易懂，而"lethal trifecta"等术语则因命名不够自明而传播受限。清晰的命名对安全概念的普及至关重要。
🔗 https://x.com/swyx/status/2041739250421436591

🎙 Podcast

Extreme Harness Engineering for Token Billionaires: 1M LOC, 1B toks/day, 0% human code, 0% human review — Ryan Lopopolo, OpenAI Frontier &amp; Symphony

OpenAI Frontier团队工程师Ryan Lopopolo花费五个月时间，借助Codex AI编程工具构建了一个超过100万行代码的企业内部工具，全程未亲自编写一行代码。最令人意外的是，项目初期一个半月的效率比手动开发慢了10倍，但通过持续搭建完善的智能体工具链，最终实现了整体效率提升10倍。团队还需不断适应每一代新模型的特性变化——例如GPT-4o引入后台Shell功能后，他们被迫将整个构建系统从Make迁移至Bazel，再到Turbo，最终定格于NX，以确保编译时间控制在一分钟以内。Lopopolo强调，AI辅助开发需要"系统性思维"：持续定位智能体的失误环节，将复杂任务拆解为更小的构建模块，而非强行让模型完成超出其能力范围的任务。
