🎙 Podcast

Extreme Harness Engineering for Token Billionaires: 1M LOC, 1B toks/day, 0% human code, 0% human review — Ryan Lopopolo, OpenAI Frontier &amp; Symphony

在这期 Latent Space 播客中，OpenAI Frontier 团队的 Ryan Lopopolo 透露，他的团队在五个月内构建了一个超过百万行代码的代码库，全程零人工编码，开发效率约为传统工程方式的十倍。他将"禁止人工写代码"作为强制约束，倒逼团队为智能体搭建完善的工具链和可复用的小型模块。一个出人意料的工程发现是：从早期模型升级到 GPT-4.1 后，Codex harness 新增了后台 Shell 功能，导致模型变得"不耐烦"，团队不得不将整个构建系统从 Makefile 依次换成 Bazel、Turbo，最终定格在 NX，只为将构建时间压缩到一分钟以内。Lopopolo 认为，当前的编程模型已足够强大，与熟练工程师在能力上基本等价，而关键的工程思维在于系统性地识别并消除智能体的失败点，而非退回到人工操作。

In this Latent Space episode, Ryan Lopopolo from OpenAI's Frontier team reveals that his team built a million-line codebase over five months without writing a single line of code themselves — and achieved roughly 10x faster development than traditional engineering. Working exclusively with Codex CLI and enforcing a strict "no human code" constraint, Lopopolo treated the limitation as a forcing function to build robust agent tooling and smaller composable building blocks. A surprising engineering insight emerged when upgrading from GPT-4o to later models: behavioral changes in the Codex harness (specifically the introduction of background shells in GPT-4.1) forced a complete build system overhaul — cycling through Make, Bazel, Turbo, and finally NX — just to keep build times under one minute so the agent wouldn't lose patience. Lopopolo argues this experience demonstrates that current coding models and harnesses are sufficiently capable to be "isomorphic" to a skilled engineer, and that the key discipline is systems thinking: identifying where the agent fails and iteratively eliminating those failure points rather than reverting to manual work.
